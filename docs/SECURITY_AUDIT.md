# 安全审计报告

本文档记录了代码中可能导致用户名密码泄露的安全问题及修复建议。

## 🔴 严重安全问题

### 1. **密码重置脚本明文打印密码** ⚠️ 高危

**位置**: `backend/scripts/reset-password.js:51`

**问题**:
```javascript
console.log(`  新密码: ${newPassword}`);
```

**风险**: 
- 密码会出现在终端输出和日志文件中
- 如果日志被访问或共享，密码会泄露
- 在共享服务器上，其他用户可能看到密码

**修复建议**: 移除密码的打印，只显示成功信息

### 2. **硬编码数据库密码** ⚠️ 高危

**位置**: 
- `backend/scripts/migrate-questions.js:11, 14`
- `backend/test-write.js:4`

**问题**:
```javascript
// ❌ 错误示例：硬编码密码
const sourceURI = process.env.MONGODB_URI_SOURCE || 'mongodb://用户名:密码@localhost:27017/mathcuz?authSource=admin';
```

**风险**:
- 数据库密码被硬编码在源代码中
- 如果代码被提交到 Git 仓库，密码会泄露
- 密码明文存储在代码中

**修复建议**: 
- 移除所有硬编码的密码
- 强制使用环境变量
- 如果没有环境变量，应该提示错误而不是使用默认值

## 🟡 中等安全问题

### 3. **前端控制台记录请求数据** ⚠️ 中危

**位置**:
- `frontend/src/components/UserLogin.vue:202, 216`
- `frontend/src/components/UserRegister.vue:110, 118`

**问题**:
```javascript
console.log("登录成功:", response.data);  // 虽然不包含密码，但可能包含其他敏感信息
console.error("登录失败:", error);        // 错误对象可能包含请求详情
console.log(response);                    // 整个响应对象
```

**风险**:
- 浏览器开发者工具中会显示敏感信息
- 如果用户截图或分享控制台输出，可能泄露信息
- 虽然密码不会被记录，但用户名等可能泄露

**修复建议**: 
- 在生产环境移除或简化 console.log
- 只记录必要的信息，不记录完整响应
- 使用环境变量控制日志级别

### 4. **密码重置 API 缺少身份验证** ⚠️ 中危

**位置**: `backend/routes/auth.js:80-104, 108-132`

**问题**: 
- `/auth/reset-password` 和 `/auth/reset-password-by-email` 接口没有身份验证
- 任何人都可以重置任意用户的密码

**风险**:
- 攻击者可以重置任何用户的密码
- 无需身份验证即可访问敏感操作

**修复建议**:
- 添加邮箱验证码机制
- 或要求提供旧密码
- 或限制为仅管理员操作

### 5. **错误信息可能泄露数据库结构** ⚠️ 低危

**位置**: `backend/routes/auth.js:32, 102, 130`

**问题**:
```javascript
console.error('注册失败:', error);
// 错误对象可能包含数据库查询详情、字段名等
```

**风险**:
- 错误日志可能包含数据库结构和字段名
- 虽然不会直接泄露密码，但可能帮助攻击者

**修复建议**:
- 在生产环境中只记录简化的错误信息
- 不要在错误响应中包含详细的技术信息

## 🟢 已实现的安全措施 ✅

### 1. **密码哈希存储** ✅
- 使用 `bcryptjs` 对密码进行哈希处理
- 密码不会以明文形式存储在数据库中

### 2. **API 响应中排除密码** ✅
- `backend/routes/auth.js:57-62` 正确排除了密码字段
- 只返回安全的用户信息

### 3. **数据库连接字符串密码隐藏** ✅
- `backend/config/database.js:32` 正确隐藏了日志中的密码

### 4. **Session 配置** ✅
- 使用了适当的 session 配置
- Cookie 设置了 httpOnly 标志

## 🔒 最佳实践建议

1. **环境变量管理**:
   - 所有敏感信息必须使用环境变量
   - 创建 `.env.example` 文件作为模板（不包含真实值）
   - 确保 `.env` 文件在 `.gitignore` 中

2. **日志记录**:
   - 永远不要在日志中记录密码
   - 限制日志中记录的敏感信息
   - 使用日志级别控制（development vs production）

3. **代码审查**:
   - 提交代码前检查是否有硬编码的密码
   - 使用工具扫描代码库中的敏感信息
   - 定期进行安全审计

4. **API 安全**:
   - 所有敏感操作需要身份验证
   - 实施速率限制防止暴力破解
   - 使用 HTTPS 传输敏感数据

5. **依赖管理**:
   - 定期更新依赖包修复安全漏洞
   - 使用 `npm audit` 检查已知漏洞
